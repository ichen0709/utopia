## 0. 先記住的三件事

1. **「示範模式 · 其他人是模擬的」橫幅只在階段一出現。** 階段二接上 Supabase 之後要拿掉(見 7.4)。
2. **訊息內容一律當純文字顯示,絕對不使用 `innerHTML`**(Svelte 也不使用 `{@html}`)。只有 `http://`、`https://` 開頭的網址會變成連結。細節見第 8 章。
3. **火熄滅時整頁變暗,但聊天文字的顏色不變、對比不降低。** 變暗的只是底色與營火場景。

## 1. 整體風格

夜晚的營火。深藍黑的底,火光用暖橘和琥珀色當重點,文字用柔和的米白。安靜、溫暖、有點手作感:圓角刻意做得不對稱(像手剪的紙),不用企業後台常見的方正卡片。

- 手機優先,**單欄**,不左右捲動。電腦版是同一個版面放大,不另做複雜版型。
- 營火場景永遠是夜晚,即使系統設為淺色。淺色模式只改聊天區、輸入區、頂部列的底色與文字色。
- 「加柴」「離開營火」「送出」三個主要按鈕,手機上高度至少 44px。

### 3.3 訊息

所有訊息:代號在上、時間在旁、內容在泡泡裡。**內容一律純文字**,長字串用 `overflow-wrap: anywhere` 自動換行。

| 類型 | 位置與外觀 |
|---|---|

### 3.4 營火

- 尺寸:火焰區 120×150px,置中在 390px 寬的場景;場景高 350px。
- 結構:木柴(兩根交叉)、餘燼、三層火焰(外、中、內)、火星(三顆)、煙(只有熄滅時)。
- 四種狀態的細節見 2.5。
- **動畫(一般模式):** 三層火焰各自以 1.3 秒、0.95 秒、0.7 秒來回搖曳(縮放與微傾斜);火星每 2.4 秒往上飄約 58px 並淡出,三顆錯開 0.8 秒;煙每 4 秒左右來回飄動。
- **加柴按鈕**在場景最下方置中(場景內 y=292)。熄滅時提示框蓋在火焰區上方。

### 3.5 線上圖示與「+N」

- 每位在線的人是一個「坐著的人」剪影(頭加肩膀),放在 34px 的圓形深色底上,顏色用該人的固定顏色;下方是代號(12px、單行、超過用省略號,最寬 64px,有黑色文字陰影確保在夜空上也清楚)。
- **六個座位**圍著火堆(手機版位置,場景座標,圖示中心):左 (50,160)、左上 (86,92)、右上 (304,92)、右 (340,160)、左下 (92,236)、右下 (298,236)。
- **自己**:圖示外圍有琥珀色雙層外框,右上角有琥珀小標籤「你」。自己固定放在左下。
- **「+N」按鈕**:在火堆正下方 (195,262),寬 76px、高 44px 的膠囊,深藍底、藍灰框、米白字,左邊有 + 號,例如「+6」。點下去開啟完整名單面板。
- 只有座位不夠(超過 6 位)時才出現「+N」。N = 總人數 − 6。
- 暫離中的人:圖示變淡(不透明度 .5),名字下面多一個小標籤「暫離中」(11px,深藍底、藍灰框、米白字)。

## 5. 手機與電腦版的差異

**原則:電腦版就是手機版的放大。** 不改變元素的順序,不拆成兩欄。

| | 手機(基準 390px 寬) | 電腦(設計稿 1280×900) |
|---|---|---|
| 版面 | 單欄,滿版 | 單欄,置中,寬約 507px(手機版的 1.3 倍),左右是夜空背景加幾顆星星 |
| 營火場景 | 390×350 | 整個場景等比放大 1.3 倍(座位、火焰、按鈕一起放大) |
| 頂部列、輸入區 | 滿寬 | 滿欄寬(507px) |
| 聊天區 | 左右內距 14px | 左右內距 20px,高度吃剩餘空間 |
| 送出鍵 | Enter 換行,用送出按鈕送出 | Enter 送出,Shift+Enter 換行 |
| 欄寬陰影 | 無 | 欄的外圍有一圈很淡的橘色光暈 |
| 觸控目標 | 至少 44px 高 | 同樣尺寸(不縮小) |

**實作提醒:**
- 欄寬用 `max-width` 限制,不要寫死 390 或 507。營火場景可以用比例縮放,或用 CSS 變數控制尺寸。
- 電腦版視窗如果比較矮(例如 800px 高),營火場景可以等比縮小,讓聊天區至少保有約 250px 的高度。
- 任何寬度下都不可以出現橫向捲動。長代號、長網址、長單字一律 `overflow-wrap: anywhere` 換行。

## 6. 減少動態效果、深色與淺色

### 6.1 深色與淺色

- **預設深色。** 用 `prefers-color-scheme` 跟著系統設定自動切換,使用者不用另外操作。
- 淺色模式的配色見 2.2。營火場景仍是夜晚(2.4)。
- 對比目標:一般文字至少 4.5:1,大字(24px 以上)至少 3:1。淺色模式的橘色重點特別調深(`#a9460c`)就是為了達到這個目標。**設計稿的對比是估算的,做前端時請用工具實際量測。**
- 顏色不是唯一的資訊來源:被 @ 的訊息有「@ 提到你」膠囊和較粗的框線;錯誤有文字說明;自己有「你」標籤和靠右位置。

### 6.2 火熄滅時的變暗

- 疊加 2.3 的變數。只改底色與框線,**不改文字色**。深色的字是 `#f4ead6`,在最暗的底色 `#05070d` 上對比非常高;淺色的字是 `#2a2016`,在變暗後的 `#e0d6c1` 上仍然足夠。
- 淺色模式變暗後,`--muted` 另外加深成 `#54463a`,確保時間等小字仍清楚。

### 6.3 減少動態效果

系統設定了 `prefers-reduced-motion: reduce` 時:

| 項目 | 一般 | 減少動態 |
|---|---|---|
| 火焰搖曳 | 三層各自搖曳 | 不動 |
| 火星 | 往上飄 | 不飄,停在原位 |
| 熄滅時的煙 | 左右飄 | 不飄 |
| 旺弱的表現 | 大小 + 亮度 | **只用大小和亮度**(2.5 的表格不變) |
| 訊息到期 | 淡出三階段 | 不淡出,到期直接消失 |
| 載入中的三個點 | 閃爍 | 不閃,固定半透明 |
| 「有 N 則新訊息」與名單面板 | 可滑入 | 直接出現 |
| 加柴冷卻的進度條 | 以長度表示 | 同左(長度不是動畫) |

聊天功能與其他行為完全不變。

## 8. 安全:訊息內容一律當純文字

這是架構文件第 9 章的要求,設計與實作都必須遵守:

1. **所有使用者輸入的內容(訊息、代號)只能用「文字」方式放進畫面。** 禁止 `innerHTML`、`outerHTML`、`insertAdjacentHTML`、`document.write`,Svelte 的 `{@html ...}` 也禁止。
2. 連結由程式碼把文字切成「普通文字片段」和「連結片段」,**連結片段只接受 `http://` 與 `https://` 開頭**(用 `new URL()` 解析並檢查 `protocol`),其他一律是普通文字。
3. 連結元素一律加 `target="_blank"` 與 `rel="noopener noreferrer"`。
4. 不做圖片預覽,也沒有任何顯示圖片的樣式。
5. 設計稿中的驗證範例:`<script>alert(1)</script> <img src=x onerror=alert(1)>` 要原樣顯示成文字;`https://example.com` 可點;`javascript:alert(1)`、`ftp://files.example.com` 不可點。這些對應架構文件 13.1、13.2 的驗證項目。

## 9. 設計的已知限制

- 設計稿是靜態畫面,動畫(搖曳、火星、飄煙、淡出)以文字和程式碼參數描述,實際手感要在前端實作時調整。
- 火的亮度分界值(2.5)、淡出階段的時間點(3.3)是建議值。
- 設計稿的色彩對比是估算,尚未用工具量測。
- 座位的位置是針對 390px 寬、最多 6 位設計;人數少於 6 位時空位怎麼排,設計稿沒有畫出,實作時再決定細節。
